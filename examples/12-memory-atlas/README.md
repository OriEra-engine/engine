# 12 · 记忆星图 / Memory Atlas

离线、零依赖、零构建的交互示例。直接导入现有
`../11-ai-cafe/engine/kernel.js` 的 `MemoryStore` 和 `Scheduler`，
展示 L9 记忆检索与 L2 系统调度；不调用大模型，也不需要 WebGPU。
这是浏览器内核示例，不是 Rust/Wasm 绑定。

## 运行

在仓库根目录执行：

```sh
python3 -m http.server 8000
```

打开 <http://localhost:8000/examples/12-memory-atlas/>。
ES module 需要 HTTP 服务，请不要双击 HTML 文件。

## 体验路径

1. 选择角色和主题，输入「灯塔」或「种子」，召回最多四段记忆。
2. 写一段新经历，设置重要性；保存后自动以新内容检索。
3. 点击「推进 7 日」：通过 Scheduler 推进时钟，并重新检索。
4. 切换角色观察独立记忆；刷新验证保存；「重置示例」恢复 18 条初始记忆。

星图只表现记忆和召回顺序，不是 embedding 投影。完整文本同时在 HTML 列表中展示，
支持键盘操作和窄屏布局。关键词没有匹配时，也可能召回重要或近期的记忆。
时间推进会改变新近度，但不保证每次改变排名。

检索由内核实现：中文双字 / 英文单词重合 × 1.6 + 重要性 × 0.45 +
`2 / (1 + elapsed)` + 主题相同加 1.2；保留分数 > 0.8 的前四条。
每个角色最多 60 条，超出时移除最早写入的记忆。

仅使用独立 localStorage 键 `oriera.memory-atlas.v1`，不会修改咖啡馆数据。
存储损坏时过滤非法条目，存储被禁用时退化为内存模式。
刷新后时钟从最新记忆日期恢复；没有写入记忆的空闲日期不保存在 localStorage。
导出的 JSON 存档包含完整世界日期，重新导入可恢复这些空闲日期。

## 回归检查

- 搜索、写入、角色隔离、推进日期、重置和刷新恢复正常。
- 浏览器控制台没有错误；没有第三方请求。
- 390px 窄屏没有横向溢出。
- localStorage 禁用、损坏内容、60 条上限、HTML 字面文本均安全处理。

## 导出与导入

点击「导出存档」下载包含三个角色和当前世界日期的 JSON 文件。
点击「导入存档」选择文件后，先查看日期与记忆总数，再点击「确认替换当前记忆」。
取消或校验失败不会改动任何记忆；导入是替换，不是合并。建议先导出备份。
文件只在本机读取，不上传。浏览器禁止持久化时仍可导入到会话内，也可以导出下载。

存档格式为 `format: "oriera-memory-atlas"`、`version: 1`、`turn` 和 `memories`。
`memories` 必须包含林舟、阿澜、小满三个数组，每个最多 60 条，总计至少一条。
每条包含 `text`（最多 180 个 UTF-16 代码单元）、`about`（灯塔/花园/港口）、
`turn`、`day`（相同整数，1–1,000,000 且不晚于世界日期）、`imp`（整数 1–5）。
文件不得超过 256 KiB；格式错误、未知版本或任一非法记忆会导致整个文件被拒绝。
额外的顶层和记忆字段不导入，未知角色被拒绝。纯 MemoryStore 导出不是本示例存档格式。

格式校验使用独立的原生 ES module，无需构建。测试只需要 Node.js 18+：

```sh
node --test examples/12-memory-atlas/save-format.test.mjs
```

浏览器回归：推进日期后导出 → 重置 → 选择存档 → 取消，确认状态未变；
再次选择同一文件 → 确认，检查日期、记忆和召回结果恢复。
再验证损坏/超限文件、刷新持久化以及禁用 localStorage 的导入和导出。
