## 为什么升级 / Why

借 DeepSeek 开源双仓库（DeepInfer / deepseek-recipe）的第一批落地。
DeepInfer 是供给侧引擎（SM100/昇腾 950），OriEra 是消费侧引擎——
本版回答的问题是：**世界模拟怎么像花钱一样地消费模型，并且让每一次
省钱看得见。**

Borrowing batch one from DeepSeek's open-source repos. DeepInfer serves
models; OriEra consumes them under a budget — and makes every saving
visible.

## 兼容性 / Compatibility

全部加法式：`TokenUsage` 加字段但 `total()` 口径不变；`ProviderOptions`
新字段默认 None；线协议在不传新选项时逐位不变（node 测试钉死默认分支）；
`next_speech`/`director_prompts` 内部重构对外部调用者不可见。

Additive only — `total()` semantics unchanged, wire byte-identical without
new options (pinned by node tests).

## 生态位声明 / Positioning

**OriEra 不做推理引擎，做推理引擎的好客户端。** 供给侧交给
vLLM / DeepInfer / SGLang；OriEra 把模型输出当作预算内资源调度。
deepseek-recipe-core（MIT）只进 `native-http` feature——wasm 与默认
构建零增量。
