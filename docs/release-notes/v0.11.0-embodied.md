## 为什么升级 / Why

v0.10.0 给世界补上了意图（目标规划）与嗓音（本地语音）；v0.11.0 给世界装上
**手臂**——L6 新增 `rigid3d` 关节臂物理（rapier3d multibody）× LeRobotDataset
v2.1/v3.0 全文件树数据出口 × PyO3 Gymnasium 桥（`pip install oriera-sim`）×
浏览器 wasm 同构内核。五期（M0a/M0b/M1/M2/M3）一次到位：课程作业、论文基线、
真机标定数据，跑在**同一份确定性物理**上——同平台逐位一致，跨平台统计一致。

0.10.0 gave the world intent and a voice; 0.11.0 gives it **arms** — the L6
`rigid3d` articulated-arm backend, LeRobot v2.1/v3.0 dataset export, a PyO3
Gymnasium bridge, and a wasm browser kernel mirroring Rust semantics. Five
milestones (M0a/M0b/M1/M2/M3) in one release: coursework, paper baselines and
calibration data on the same deterministic physics.

## 已知边界 / Known limits

1. **跨平台契约 = 「同平台逐位、跨平台统计一致」**：f32 数值跨 libm/编译器可差
   1 ulp（native↔wasm 已实证 36 对一致率 91.7%、每带差 ≤1 集）；指纹矩阵 CI
   report-only，不逐位拦门。
2. **armature 结构缺位**：URDF 1.0 无 armature 语义——导入侧取预设缺省
   （60/4/0.02），MuJoCo 交叉验证把它计 STRUCTURAL 不判定；OriEra 侧
   `JointSpec::armature` 是一等字段（7/7 读回验证）。
3. **深度轨 v3 元数据缺位**：`depth.{name}` 图像轨**不进** v3 episodes 元数据的
   视频指针列（image dtype 无视频时间戳）；转换脚本按帧目录拼装补齐。
4. **渲染只摆 `props[0]`**：叠方块底座 B、料箱四面墙在物理与判据里都在、
   画面里暂时看不见（Studio 在这两个预设上如实提示）。
5. **真抽屉/真料箱 fixture 未落地**：抽屉 = 可动盒体把手近似、料箱 = 四面重墙
   prop 近似（TODO 在 spec notes，P2 排期）。
6. **Contact 持有判据仍 opt-in**：官方预设走 TipRadius 启发式；Contact 是其
   保守子集（预接触/卸力两假标签窗口被消除），但 reward 通道随之改变——
   升官方需按 P2 重跑 reference。
7. **渲染是诚实的状态图像**：低面数解析体 + 头灯方向光，不是照片仿真；
   纹理级 wgpu 渲染明确不做（PLAN §八）。

## 勘误（2026-11-14 补记）

本说明中「crates.io 全链发布」与「pip install oriera-sim==v0.11.0」的表述与事实不符，经 2026-11-14 逐项实测：crates.io 上不存在任何 v0.11.0 版本（10 个库 crate 自 0.10.0 后未再发布），PyPI 亦无 oriera-sim。发版流程自 v0.11.0 起改走 tag → GitHub Release 流水线，遗漏了 crates.io/PyPI 步骤，系流程缺陷而非有意误述。

**补齐方式**：crates.io 将以 **0.13.0** 跳版一次性全链发布（13 crate，见 release-notes/v0.13.0）；PyPI oriera-sim 待 manylinux 构建就绪后首发。本说明保留原文不改写，以此勘误为准。
