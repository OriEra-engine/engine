## 一句话

把"速度 → 状态 → 关节面板"补上：Idle/Walk/Run 三态、阈值两侧留迟滞带、切态交叉淡入，输出正好是步 1c 蒙皮路径要的 `[[f32;4];4]` 面板。

## 一、为什么和 027 分开

路线二第二档是"NavMesh + 简单动画状态机"，两件事没有代码耦合：导航决定往哪走，动画决定走起来长什么样。分开两刀，各自可独立评审、独立回滚；合起来就是一个 1650 行的补丁，越过单人仓库的线。

## 二、做了什么

| 接口 | 行为 |
|---|---|
| `Keyframe` | 时间 + 位置 + 四元数 + 缩放；`Keyframe::at(t, pos)` 是只有平移的简写 |
| `JointTrack` / `AnimationClip` | 每关节一条 TRS 轨道；剪辑 `duration` 秒循环，`sample_into(t, &mut palette)` 按 `t.rem_euclid(duration)` 折相位，缺轨道的关节输出单位矩阵 |
| `trs_matrix(k)` | TRS → 行主序 4×4（平移在 `m[0..3][3]`，底行 `[0,0,0,1]`），与渲染侧 `update_skeleton` 同一约定 |
| `blend_matrices(a, b, w)` | 逐元素线性插值。**是近似**，文档里写明大角度旋转会缩水 |
| `ClipBank` | idle / walk / run 三段剪辑 + `joint_count()`（取三者最大，决定面板长度） |
| `AnimController` | `walk_at` / `run_at` / `hysteresis` / `fade_time`；`sample(dt, speed, bank)` 推进相位并产出面板；`force(state)` 硬切（也走淡入）；`state()` / `clock()` 只读 |
| `Locomotion` | Idle / Walk / Run |

三条值得单说的决定：

**迟滞带的语义写死在 `target_state` 里。** 进 Walk 要 `speed > walk_at + h/2`，回 Idle 要 `speed < walk_at - h/2`；Run 同理。带内维持现状——否则 NPC 速度在阈值附近抖一帧，动画就闪一次。

**切态相位归零、旧状态相位留一份。** 淡入期两段剪辑同时采样、按 `1 - fade/fade_time` 混合。淡入结束后清掉旧状态，不留悬挂状态。

**`dt <= 0` 或 NaN 不推进相位，但仍返回面板。** 时间冻住时调用方拿到的是上一帧姿态，不是空 vec——很多实现会在这里返回空指针或 panic。

## 四、诚实边界

- **混合是矩阵线性插值，不是姿态插值。** 大角度旋转会缩水（矩阵条件数变差、长度小于 1）。要正确得在四元数或双四元数空间做，本步不做，写在模块头与 STABILITY 里。
- 只驱动关节：不做 IK、不做根运动、不做脚部贴地。
- 状态只有三态且由速度标量驱动：没有事件轨道、没有动画事件回调；要打断就 `force`。
- 剪辑必须自带关节完整姿态；缺的按单位矩阵补，不做父级继承推导——所以给真实 GLB 骨骼用时，得先做一遍 bind 空间烘焙。
- 相位是 `f32` 累加：长跑会积累误差（按 60fps 估算十分钟量级在毫秒），回放对齐以帧号为准，不要以相位为准。
- **和步 1c 的接缝还没接**：`AnimController::sample` 输出的面板要喂给 `update_skeleton`，这层接线（每帧给每个 NPC 各自一份骨架、面板长度对不对得上 `max_joint`）要等"低多边形场景 + NPC 实例"落地时一起做，那时才知道每骨架一份 uniform 的容量够不够。本步只保证数据形状正确。
